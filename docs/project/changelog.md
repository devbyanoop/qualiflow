# Changelog

## Unreleased

- Repo scaffolding: `LICENSE` (Apache-2.0), `.gitignore`, `README.md`, CI skeleton (`.github/workflows/ci.yml`), this documentation site.
- M0.1 infra: `docker-compose.yml` (Postgres 16 + pgvector, Redis, MinIO, OTel Collector, Prometheus, Grafana) against the remote `fedora-host` Docker context. See `project/roadmap.md` for the real-world gotchas hit along the way (missing compose plugin, MinIO image distribution changes, remote-context bind-mount limitation).
- M0.2 API skeleton: `apps/api` (FastAPI), Keycloak container + realm/client, JWT-gated `/protected` endpoint, OTel metrics flowing to Prometheus, first unit tests + CI wired to run them.
- M0.3 tenant isolation: `organizations`/`projects` with Postgres RLS, a restricted non-superuser app role, per-request org scoping, and a leak test verified red-without/green-with the policy. New `integration` CI job with its own Postgres service container.
- M0.4 first LangGraph node: `apps/agents`, a tier-resolved one-node graph calling Groq with strict structured output, logged cost/latency (no tracing backend), exposed via a live `/hello/{name}` endpoint. Test is deliberately real (no mocking) — new `agents` CI job, needs a `GROQ_API_KEY` secret once pushed.
- M0.5 reference fixture: pivoted away from a QualiFlow-owned `demo-apps/` folder to **NovaPay** (separate, pre-existing repo) as the standalone app-under-test. `fixtures/novapay/openapi.yaml` (validated) and `brd-transfer-rule.md` describe it; three real authorization/consistency gaps found in NovaPay's transfer API along the way.
- M0.6 ingestion v0: `apps/knowledge`, real delta-hash skip proven against self-hosted embeddings (switched from BGE-M3 to a smaller multilingual model after repeated OOM kills — see roadmap for the full incident, including a close call with the host itself). Also fixed a real uvicorn/Windows event-loop bug (`uvicorn.run()` hard-codes `ProactorEventLoop`, ignoring any policy set) and a SQLAlchemy `text()` + Postgres `::` cast collision.
- M0.7 first real generation: `generate_tests.py` (retrieve → draft, real Groq call, strict structured output), full positive/negative/edge test matrix against real infra. Same Windows event-loop bug recurred in a third package (`apps/agents`) — same fix, different place it was missing.
- M0.8 human review gate: LangGraph `interrupt()` + a real Postgres checkpointer, `/generate` + `/review/{thread_id}`, `case_reviews` table. Proven by actually killing the server mid-review and resuming from a fresh process. Full positive/negative/edge/regression test matrix, the latter simulating the kill/restart proof with an independent checkpointer connection.
- M0.9 first automated script: `api_automation_agent.py` generates and dry-runs a real pytest file against NovaPay's live API on approve/edit. Passed for real, then deliberately broken to confirm it fails for the right reason. A permanent `xfail(strict=True)` test cashes in M0.5's deferred promise — a generated-style test that genuinely catches NovaPay's known ownership-check gap. Two real bugs found (invented account IDs, invented credentials) fixed by having the agent resolve real values itself rather than let the LLM guess. NovaPay-dependent tests skip cleanly in CI via a `requires_novapay` marker.
- M0.10 minimal evidence hashing (**Walking Skeleton complete**): `evidence.py` hashes each dry run's real script and output (SHA-256), stores both plus a manifest in MinIO, persisted alongside the `automated_scripts` row (new `evidence` JSONB column). Proven standalone and through the live HTTP `/generate`→`/review` flow end-to-end; that same real run's dry run genuinely failed (a refNo-format mismatch in the generated assertion), confirming evidence capture doesn't launder failures into false passes. Full positive/negative/edge/regression test matrix against the real MinIO instance. Also fixed a stale `test_generate_tests.py` left broken by M0.8's `build_graph` refactor, which was silently blocking the whole `apps/agents` test suite from collecting.
- Generalized `api_automation_agent.py` past NovaPay: removed the hardcoded `NOVAPAY_URL`, fixed OpenAPI spec path, default credentials, and the bank-account-specific `resolve_two_own_accounts()` function. New `target_apps` table (registered via `POST /targets`) holds a base URL + OpenAPI spec per org/feature; a generic LLM-written-and-executed resolver script discovers whatever real values a case needs, with no app's domain model hand-coded in source. NovaPay is now just the first registered target, proven through the same generic path everything else uses. A new static regression test asserts "novapay" never appears in `api_automation_agent.py`'s source again.
- Real onboarding docs: `installation.md` and `quickstart.md` filled in (were stub placeholders), plus a new `infra/keycloak/provision-realm.sh` codifying the realm/client setup that previously only existed as commands run by hand. Every step run live against the real stack, including a full automate+evidence pass against NovaPay. Found and documented a real `uv` workspace gotcha (`uv sync --project apps/X` evicts sibling apps' editable installs — use `uv sync --all-packages` + `--no-sync`) and a real product-level constraint (a `/generate` `thread_id` can only be reviewed once; no retry-in-place).
- Phase 0 begins: six ADRs for decisions already made during the build (`docs/adr/0001`–`0006`), plus a first real safety guardrail — **environment classification + production-block middleware** (§8.5, [ADR 0007](../adr/0007-environment-classification.md)). Every `target_apps` row now requires an explicit environment (production/pre-production/uat/qa/dev), enforced at both the API and database layers; `/review` blocks automation against a `production` target with `403` unless `"allow_production": true` is explicitly set. Proven live both directions against a real target. Full positive/negative/edge/regression test matrix (10 tests). Docs site built for the first time under strict mode — it had only ever been written, never verified to actually build.
- Bilingual (EN+AR) demo BRD (`fixtures/i18n-demo-brd.md`): ingested and generated against live for real. A near-miss along the way — a shell pipe made correctly-encoded Arabic/UTF-8 *look* corrupted in the terminal — was investigated at the byte level and confirmed to be a local display artifact, not a real bug. Full positive/negative/edge/regression test matrix for Unicode round-tripping through ingestion (5 tests, real embeddings calls).
- `apps/web`: the first UI, scoped deliberately to Phase 0's i18n/RTL shell only (no backend integration — a bigger, separate decision). Next.js 16 + TypeScript + Tailwind + `next-intl`, locale-prefixed routing (`/en`, `/ar`), every string externalized, `<html lang>`/`dir` set per locale in one place. Proven live: both static locale routes built and served, `dir="rtl"` confirmed for Arabic, 880 real Arabic characters confirmed present at the codepoint level in the rendered response. First JS app in the repo — added a root `pnpm-workspace.yaml` alongside the existing `uv` workspace, after catching and fixing a nested-lockfile conflict `create-next-app` left behind.
